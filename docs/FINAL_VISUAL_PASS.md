# Final onboarding visual pass

This pass preserves authentication/session decisions, tenant authorization, onboarding revisions, private-logo adapter behavior and MiniStack configuration. It adds no business features, dependencies or external imagery. Unrelated `.gitignore`, staged `apps/api/.env.example` deletion and `docs/AUTHENTICATION.md` changes are excluded from the commit.

The screenshots were opened for actual visual review. This exposed a stretched day-label cell despite aligned status/time controls; `align-items: start` corrects that issue, with a new day/status/input geometry assertion. The first review business action was also top-aligned. Affected browser checks and captures were rerun after rebuilding.

An unmatched search produces zero selectable options; Escape restores trigger focus. Invalid hex input blocks progression. Seven-day flags, copied intervals, retained/replaced/removed logo behavior and real verification/password-reset flows remain covered.

## Checks and limits

All passed, run sequentially: `pnpm check`, `pnpm build`, `pnpm nx run web:onboarding-check`, `pnpm nx run web:verification-check`, `pnpm nx run web:product-check`, `pnpm e2e:web`, `pnpm nx run api-e2e:auth-check`, `pnpm nx run mobile:auth-native-bundle`. Results: 29 workspace check tasks, 5 build tasks, full onboarding/verification matrices, 150 route/theme/viewport combinations and both themes’ interaction flows, 2 Chromium smoke tests, 13 authentication integration groups, and Android Metro/Hermes export. Node 24.20.0 and pnpm 11.25.0 were used. Local preview uses port 3010 and isolated API port 3302; email is forced to local Mailpit. Browser fixtures are cleaned up by the existing scripts.

Verification outage/anonymous-success captures use explicit mocked responses; authenticated success and invalid-token handling use the real API. MiniStack upload/read/replacement/removal checks are local-emulator evidence only. This pass does not establish production S3 compatibility or change the previously documented emulator private-access limitations. No presigned URL behavior is introduced. Native source checks and bundle export are distinct from unavailable device verification.
