# Security and code-quality audit — 2026-10-04

This reviews the current implementation and pending project work. It is not a production certification. No database reset, shared-service outage, external mail, production load test, or push was performed.

## Scope and trust boundaries

The repository-wide source inventory and static searches covered application/shared source, tests and operator scripts, schema/migrations, configuration, CI and local infrastructure. Manual review concentrated on reachable security paths: Nest controllers/services, credentials/cookies/CSRF, email lifecycle, Redis Lua, tenant transactions, image decoding/S3, Next server modules/proxy and authoritative route policy, Expo credential lifecycle/storage/deep links, shared contracts and validation. Presentation/demo code was reviewed through source/sink searches, module-boundary checks and rendered regression flows; this is not a claim of exhaustive manual proof for every presentation line.

Browser → same-origin Next proxy → Nest → PostgreSQL/Redis/SMTP/S3 is the web boundary. Native uses bearer access plus rotated refresh credentials, with only refresh secrets in SecureStore. Both clients consume authoritative server identity/workspace completion. Demo fixtures and local cosmetic state have separate explicit entry points and supply no real account metrics. Admin remains a starter; only its shared Next security dependency changed.

Tracked text and pending changes were checked for private keys and common cloud/provider credential patterns; no private external credential was identified. Sample local-development service credentials exist in examples and must never be reused for production. Local environment contents are excluded. This targeted scan does not certify Git history or every possible secret format.

## Dependency evidence and unresolved advisories

The final lockfile audit reports **0 critical, 3 high, 2 moderate** advisories (down from 56 total, including 2 critical and 31 high). These are advisory counts, not a count of demonstrated exploitable application endpoints.

The compatible mysql2 3.23.1 tooling patch also resolves its high [protocol advisory](https://github.com/advisories/GHSA-3f6p-5ww8-9rcr) and moderate [compression advisory](https://github.com/advisories/GHSA-rgwj-5xj2-c3m3); the application continues to use PostgreSQL.

Primary Next/Sharp references: [Server Actions DoS](https://github.com/vercel/next.js/security/advisories/GHSA-m99w-x7hq-7vfj), [AVIF optimization](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4), [Windows RCE](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36), [OG ImageResponse advisory](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j), [Sharp advisory](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c). The selected Next version also avoids the newer OG advisory; this app currently does not use ImageResponse.

**Unresolved high dependency advisories:**

- [deepmerge-ts](https://github.com/advisories/GHSA-ggr8-5vv4-36mx), via Prisma configuration tooling. Trigger needs recursive JavaScript object graphs; ordinary HTTP JSON cannot contain cycles. Fix requires major 8 upgrade, not a blind override of Prisma's expected dependency.
- [node-forge](https://github.com/advisories/GHSA-86w9-cpqp-85rv), via Expo code-signing tooling. No patched version is reported. Certificate/signature processing needs follow-up with Expo/upstream; absence of an observed API path is not proof of safe native delivery tooling.
- [braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), in glob/Metro tooling. No patched version is reported. Current configuration patterns are trusted; do not accept untrusted glob patterns or expose development bundlers publicly.

Remaining moderate advisories also include [uuid](https://github.com/advisories/GHSA-w5hq-g745-h8pq) in Expo/xcode tooling and [decode-uri-component](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr) in query-string. Expo Router imports query-string in path parsing, so the latter must **not** be dismissed as tooling-only: malformed native deep links may reach decoding before app validation. The maintainer [release notes](https://github.com/SamVerschueren/decode-uri-component/releases/tag/v0.4.0) confirm the newer decoder moves to ESM, while current query-string uses CommonJS require and expects a callable export. A blind 0.5 override is therefore incompatible. Follow-up needs compatible upstream integration and a native parsing regression test; this exposure remains open.

No unresolved critical advisory is reported by the final registry audit. No additional demonstrated unresolved high API authorization flaw was identified. The unresolved high dependency advisories above remain real maintenance obligations.

## Boundaries and production checks

- MiniStack returned **200 for anonymous direct object access despite private application intent**. The application exposes logos through membership-authorized API reads and the emulator binds to loopback; the emulator does not establish bucket/IAM privacy. Production must verify real bucket public-access blocking, least-privilege IAM, authenticated read behavior and removal/retention rules against the selected provider. No presigned URLs are used. Persistence/restart testing was not repeated during this audit because it would restart the shared emulator; prior reports are not counted as new evidence.
- Production must exercise HTTPS/Secure host cookies, trusted ingress and actual client-IP attribution, CORS, TLS/HSTS, SMTP delivery and failure recovery, S3 policies and restore/cleanup scheduling. The BFF default strips forwarding headers: clients share the proxy IP budget unless a protected ingress safely overwrites forwarding headers and both proxy/API trust are explicitly configured. This can produce aggregate-IP denial; the cross-IP rate test proves the service policy, not every deployment topology.
- Request byte caps do not replace ingress connection/time budgets or volumetric protection. Set slow-body/header/connection limits at the production edge. No load test was performed.
- Inline-compatible CSP remains weaker than a nonce/hash policy. Do not weaken validation/escaping because CSP exists.
- No actual Android device/emulator execution was available. SecureStore and routing were reviewed/tested in code; native credential endpoints were tested on the real API. Android backup/plugin behavior and release transport/deep-link runtime still need device verification. [Expo SecureStore documentation](https://docs.expo.dev/versions/latest/sdk/securestore/) describes default Android backup exclusion; the existing plugin is enabled, but compiled device backup behavior was not certified.
- Failed native server logout attempts local credential removal and immediately invalidates in-memory state; revocation cannot be guaranteed during outage. Failed physical SecureStore removal can leave a credential across process restarts, so device storage behavior remains a verification need. Absolute server expiry/revocation checks remain active.
- Targeted source review and automated checks do not prove the absence of all vulnerabilities; remaining SMTP enumeration and native decoder exposure are explicit above.
